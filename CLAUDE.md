# CLAUDE.md

Указания для Claude Code при работе с этим репозиторием.

Проект русскоязычный целиком: код, докстринги, комментарии, сообщения коммитов,
промпты, README и общение с владельцем — по-русски.

## Что это

**Mco mag** (`@mcomagazine`) — Telegram-канал об одежде, которую носят осознанно:
откуда взялась вещь, кто её придумал и почему она выглядит именно так. Сервера
нет: всё крутится на GitHub Actions, состояние — обычные JSON-файлы репозитория,
git работает бесплатной базой с историей и откатом.

Ниша, рубрики, тон и порядок работ описаны в [ЗАДАНИЕ.md](ЗАДАНИЕ.md) — это
исходное техзадание владельца, и оно остаётся источником правды по продукту.
Инструкция для владельца — в [README.md](README.md).

Канал — не самоцель, а актив: трафик копится под продажу рекламы магазинам
и нативные интеграции мультибренда одного из авторов.

## Команды

```bash
.venv/bin/pip install -r requirements.txt
.venv/bin/python -m src.<модуль> [флаги]
```

Тестов и линтеров нет. Проверка изменений — «сухими» прогонами: они ничего
не пишут и не тратят токенов.

```bash
python -m src.publish --check         бот, канал, права, размер очереди
python -m src.compose --dry-run       план генерации без затрат
python -m src.publish --dry-run       что ушло бы в канал
python -m src.moderate --dry-run      какие нажатия накопились
python -m src.commons --dry-run       какое фото нашлось бы очереди
python -m src.cover --demo            нарисовать карточки-заглушки и глянуть
```

Рабочий конвейер:

```bash
python -m src.compose --submit        отправить пачку в Batch API (вдвое дешевле)
python -m src.compose --fetch         забрать готовое в очередь
python -m src.compose --now 3         написать 3 поста сразу (дороже, для отладки)
python -m src.compose --now 1 --rubric worn   пробный пост рубрики, ещё не включённой в ленту
python -m src.publish --target admin  следующий пост себе в личку с кнопками
python -m src.publish --preview-all   вся очередь на просмотр, не публикуя
python -m src.moderate --serve 55     дежурство: разбирает нажатия за секунды
```

`.env` (по образцу `.env.example`) читает собственная `config.load_dotenv()` —
пакет `python-dotenv` не нужен и не установлен.

## Архитектура

### Конвейер

Три независимых шага, связанных только файлами состояния:

1. **[src/compose.py](src/compose.py)** — берёт неиспользованные сюжеты
   из курируемых баз и пишет посты в `content/queue/*.json`. Там же ищется
   иллюстрация: картинка должна попасть в пост до превью, иначе ведущие
   утвердят одно, а в канал уйдёт другое. Батч асинхронный
   намеренно: один запуск `--submit` отправляет задание, следующий `--fetch`
   забирает — Actions не должен часами ждать ответа.
2. **[src/publish.py](src/publish.py)** — берёт самый ранний файл очереди.
   **Смотрит не на часы, а на время прошлой публикации**, поэтому пропуск крона
   (обычное дело на бесплатном тарифе) ленту не ломает. Опубликованное уходит
   в `content/archive/` и `data/posted.json`.
3. **[src/moderate.py](src/moderate.py)** — единственный поллер: разбирает
   нажатия кнопок «В канал» / «Удалить» под постами в личке владельца.

### Правки формата приходят из бота, а не из этой сессии

Под каждым превью в личке есть кнопка **«✏️ Поправить»**. Она не трогает
очередь: бот присылает приглашение, ведущий отвечает на него — замечанием
или переписанным текстом поста целиком, — и ответ ложится в
`data/feedback.jsonl` вместе с оригиналом поста.

Так устроено потому, что **формат канала правит владелец, а не модель**:
у второго ведущего (@sfmmfu) нет доступа к Claude, и его правка иначе
до кода не доходит вовсе.

**Читай `data/feedback.jsonl` перед любой правкой промптов, голоса канала
и отбраковщика.** Это единственное место, где записан живой вкус ведущих:
чего в постах слишком много, где тон не тот, какой заголовок они считают
нормальным. Задание и голос канала описывают замысел, правки — то, что
получилось на самом деле. Расходятся — прав журнал правок.

Текст поста в очереди правка не подменяет: отличить замечание («сделай
короче») от присланного эталонного текста надёжно нельзя, а подменять пост
фразой «сделай короче» — худший из возможных исходов.

### Ключевые узлы

- **[src/config.py](src/config.py)** — единственная точка правды: пути, секреты,
  лимиты, `RUBRICS` с весами, `ACTIVE_RUBRICS` и поля рекламы. Меняешь поведение
  канала — почти всегда здесь. Пути к данным берутся отсюда, вручную не собирай.
- **[src/state.py](src/state.py)** — всё чтение и запись состояния. `read_json`
  при битом файле переименовывает его в `.broken` и возвращает пустое состояние:
  один испорченный JSON не должен ронять запуск.
- **[src/llm.py](src/llm.py)** — генератор за фасадом. Ответ жёстко ограничен
  `POST_SCHEMA`, свободный текст не разбирается. Голос канала уходит в system
  с `cache_control: ephemeral` — он одинаков во всех запросах.
- **[src/commons.py](src/commons.py)** — иллюстрация к посту: фото вещи
  с Wikimedia Commons. Лицензию проверяет машина (NC и ND каналу с рекламой
  нельзя, непустое `Restrictions` — тоже мимо), атрибуция собирается в коде
  и уходит в подпись: без неё фото не отправляется вовсе.
  `rank()` оценивает кандидатов по трём уровням — та самая вещь, вещь по теме
  сюжета, вещь бренда — и берёт лучшего из всех запросов, а не первого
  подошедшего. Уровни нужны оба раза по делу: без проверки слов посту про
  кампанию Stone Island достаётся каменный дом на Большом Заяцком острове,
  а без ассоциации по теме — вообще ничего, потому что фото отменённого
  сэмпла Nike SB нет и не будет. Ассоциативное фото подписывается прямо —
  «На фото не предмет поста»: выдать похожую вещь за ту самую это то же
  вранье, что выдуманный год.
- **[src/cover.py](src/cover.py)** — карточка с заголовком на Pillow:
  заглушка для постов, которым фото не нашлось. Рисуется на месте при отправке,
  в системный временный каталог, и в репозиторий не кладётся: воркфлоу коммитят
  `content/` обратно, и картинки распухли бы в историю git. Шрифт берётся
  с диска — встроенный в Pillow кириллицы не знает; нет шрифта — пост уходит
  текстом.
- **[src/quality.py](src/quality.py)** — отбраковка перед очередью: служебный
  JSON вместо текста, запрещённые обороты, слова-пустышки, отсутствие вопроса
  в конце и — главное — **годы, которых нет во входных данных**.
- **[prompts/voice.md](prompts/voice.md)** — самый важный файл продукта, тон
  канала; правила рубрик — в `prompts/rubrics/*.md`.
- **[ПРОМПТЫ.md](ПРОМПТЫ.md)** — эстафета задач: готовые промпты для следующих
  сессий. Каждая сессия доделывает свой пункт и переписывает файл под то,
  что осталось. Так работа продолжается без пересказа контекста заново.

### Правила, которые нельзя нарушать

- **Ничего не выдумывать.** Модель не держала вещь в руках и не была на показе.
  В посте только то, что проверяется по данным: год, город, имя конструктора,
  ткань, патент, тираж, где продавалось. «Культовая вещь, ставшая символом
  эпохи» — вычёркивается отбраковщиком.
- **Курируемые базы в `data/` пополняются вручную, и это ядро ценности канала.**
  У конкурентов пересказ пресс-релиза, здесь проверенный факт. Wikipedia
  и Wikidata — добирающий источник с меньшим весом. Молчат оба — пост
  не пишется, а запрос падает в `data/gaps.jsonl`: это список работы
  по реальному спросу.
- **«НЕ ВЫШЛО» — самая опасная рубрика.** Запись без ссылки на подтверждение
  постом не становится, и дополнять её «правдоподобными» подробностями нельзя.
  Это должно быть прямым текстом в промпте рубрики.
- **Проверяй даты и авторство перед записью в базу.** В моде ходит много
  красивых легенд, которые не подтверждаются. Расхождения источников пиши
  в поле `notes` — модель обязана про них знать.
- **Запись без ссылок в базу не кладётся и в план не попадает.** Фильтр стоит
  в `compose.curated_items()`, но полагаться на него нельзя: он ловит пустое
  поле, а не выдуманную ссылку.
- **Единица контента — сюжет, а не бренд.** У одного бренда в `stories`
  несколько сюжетов, каждый даёт свой пост. Поэтому двадцать брендов — это
  сотня постов, а не двадцать.

## Работа с GitHub Actions

Все воркфлоу в `.github/workflows/` коммитят изменённое состояние обратно.
Отсюда два обязательных приёма для любого нового воркфлоу, пишущего в `data/`
или `content/`:

- `concurrency: group: state-write` — два одновременных запуска подрались бы
  при коммите;
- `git pull --rebase --autostash origin ${{ github.ref_name }}` перед `git push` —
  между checkout и push мог пройти другой воркфлоу.

Журналы `data/*.jsonl` объявлены `merge=union` в [.gitattributes](.gitattributes):
локальный запуск иначе конфликтует с автоматическим.

`PUBLISH_TARGET` (Actions → Variables) переключает `admin` ↔ `channel`: пока
`admin`, посты уходят ведущим в личку с кнопками «✅ В канал» / «🗑 Удалить».

**Канал ведут двое.** `TELEGRAM_ADMIN_ID` — список id через запятую, разбирает
его `config.admin_ids()`; напрямую `secret("TELEGRAM_ADMIN_ID")` больше
не используется нигде. Превью уходит каждому, нажатие принимается от любого:
кто первый нажал, тот и решил, второму кнопка ответит, что поста в очереди уже
нет. Клавиатура убирается в том чате, где нажали, — `chat_id` берётся
из события, а не из настроек.

## Ограничения площадок, о которых надо помнить

- **Bot API не отдаёт просмотры постов** — ни чужих, ни своих. Цифры для
  медиакита придётся брать из статистики канала в клиенте либо через MTProto
  с обычного аккаунта. Это отдельное решение владельца, молча подменять его
  выдуманными цифрами нельзя.
- **Токен `erid` выдаёт ОРД**, а не Telegram и не мы: рекламодатель регистрирует
  креатив и отдаёт токен. Поля в модели поста есть (`kind`, `advertiser`,
  `erid`), маркировка приклеивается в `publish.render()`, но получение токена —
  ручной шаг.
- **Картинки — юридический риск.** Пресс-фото брендов и кадры показов
  для канала, который продаёт рекламу, брать нельзя. Рабочие источники:
  собственные съёмки магазина, Wikimedia Commons с проверкой лицензии,
  свои карточки-шаблоны. Работают сейчас первое и третье: `src/commons.py`
  ищет фото на Commons при постановке поста в очередь, а `src/cover.py`
  рисует карточку тем постам, которым не нашлось вообще ничего. **Карточка —
  последняя страховка, а не решение:** владельцы канала об одежде хотят
  видеть вещь, и плашка с заголовком поста их не устраивает. Поле `cover`
  у поста — точка расширения: положишь туда ссылку руками, и поиск её
  не тронет.
- **Instagram Reels и TikTok из России не автоматизируются** надёжно — для них
  делается выгрузка файла и текстов, а выкладывает человек. VK Клипы
  и YouTube Shorts автоматизируются, но загрузка из России может падать.

## Стиль

- **Докстринг модуля объясняет решение, а не перечисляет функции**: чем модуль
  занят, почему сделан именно так, какая альтернатива отвергнута и почему,
  ниже — примеры запуска. Комментарии в коде — про «почему»; ограничения
  площадок описывай прямо на месте, где они мешают.
- **Сообщения коммитов по-русски**, обычной фразой о смысле изменения,
  без conventional-commits и англоязычных префиксов.
- У каждого модуля — CLI с «сухими» режимами (`--check`, `--dry-run`).
  Владелец должен иметь возможность проверить любой шаг, не трогая канал.
- Python 3.12 в CI, `from __future__ import annotations` в каждом модуле,
  argparse с русскими `help`, зависимостей минимум — три в
  [requirements.txt](requirements.txt) (`anthropic`, `requests`, `Pillow`
  для обложек), и список стоит держать таким.
- Когда упираешься в ограничение чужого API — пиши об этом владельцу прямо,
  а не обходи молча.
