# Эстафета: что делать в следующих сессиях

Файл существует, чтобы новая сессия Claude не пересказывала контекст заново
и не жгла на это токены. В нём — очередь задач и готовые промпты: скопировал
верхний, вставил в новую сессию, работаешь.

**Правило для каждой сессии:** доделал пункт — вычеркни его отсюда, а то,
что всплыло по дороге, впиши новым пунктом с готовым промптом. Файл
переписывается до тех пор, пока в нём не останется пусто: тогда работа
закончена.

Промпт пишется так, будто у читающей сессии нет никакого контекста: что
сделать, где лежит нужное, чем проверить результат. Всё общение — по-русски.

---

## 1. Разобрать правки ведущих и переписать промпты

Главный пункт. Пробные посты всех четырёх рубрик ушли в бот ведущим
(@molodyedengi и @sfmmfu) с кнопкой «✏️ Поправить». Их ответы копятся
в `data/feedback.jsonl`. Пока правок нет — ждём; появились — это ценнее
любого задания, потому что там живой вкус владельцев канала.

```
Прочитай CLAUDE.md и data/feedback.jsonl в /Users/mke/Mco-mag.
В журнале — правки ведущих канала к пробным постам: поле fix (что сказали),
original (текст поста, к которому это относится), rubric, author.

Разбери все правки и внеси их в продукт:
— общие замечания по тону, длине, структуре — в prompts/voice.md;
— замечания к конкретной рубрике — в prompts/rubrics/<ключ>.md;
— повторяющиеся обороты, которые ведущие вычёркивают, — в BANNED_PHRASES
  или FILLER_WORDS в src/quality.py;
— если прислали свой вариант текста поста целиком, разбери, чем он отличается
  от исходного, и опиши разницу правилом в промпте. Не вставляй чужой текст
  в промпт целиком: пример на один бренд модель начнёт копировать дословно.

Не выдумывай правил, которых ведущие не просили: правишь ровно то, что сказали.
Потом покажи, что изменилось, и сгенерируй по одному новому пробнику рубрик,
которых правки касались: python -m src.compose --now 1 --rubric <ключ>,
затем python -m src.publish --preview-all.
Отчитайся по-русски. Обнови ПРОМПТЫ.md: этот пункт вычеркни, впиши то,
что осталось.
```

## 2. Включить в ленту рубрики, чей формат утвердили

Пока `ACTIVE_RUBRICS` в `src/config.py` — только `history`. Остальные три
пишутся флагом `--rubric` и в очередь сами не попадают. Когда ведущие скажут
«формат ок» — включать, но не раньше: в базах `celebrities.json`,
`unreleased.json`, `fresh.json` лежит по несколько записей, и лента их съест
за пару дней.

```
В /Users/mke/Mco-mag прочитай CLAUDE.md. Ведущие утвердили формат рубрик:
<перечисли, каких именно>.

1. Пополни курируемые базы этих рубрик до 12-15 записей каждую
   (data/celebrities.json, data/unreleased.json — формат смотри в файлах).
   Факты ищи в вебе и проверяй: каждая запись со ссылками, ничего по памяти.
   Правило рубрики НЕ ВЫШЛО жёстче общего — без ссылки на подтверждение
   запись не кладётся вовсе.
2. Добавь ключи рубрик в ACTIVE_RUBRICS в src/config.py.
3. Проверь план: python -m src.compose --dry-run — в нём должны появиться
   новые рубрики в пропорции весов из RUBRICS.
Отчитайся по-русски и обнови ПРОМПТЫ.md.
```

## 3. Автосбор поводов для рубрики НОВОЕ

`data/fresh.json` пока заполняется руками, а по заданию НОВОЕ — единственная
рубрика на автосборе. Ленты уже проверены и лежат в `data/feeds.json`.

```
В /Users/mke/Mco-mag прочитай CLAUDE.md и ЗАДАНИЕ.md (раздел про рубрики).
Напиши src/collect.py — сборщик поводов для рубрики НОВОЕ:
читает ленты из data/feeds.json, складывает свежие записи в data/fresh.json
в том же формате, что там уже лежит (items с полями brand/what/when/angle/
facts/sources/used), повторы отсекает по data/seen.json через state.fingerprint.

Ограничения проекта: зависимостей минимум (requirements.txt — две, список
держать таким; RSS разбирать стандартным xml.etree, а не feedparser),
CLI с --dry-run, докстринг модуля объясняет решение, всё по-русски.

Важно и должно быть видно в коде: пресс-релиз сам по себе поводом не является —
у записи должна быть связка с историей бренда, иначе пост будет как у всех.
Как минимум оставь в записи поле для такой связки и не пускай в план записи,
где facts пусты (фильтр уже есть в compose.curated_items).

Добавь воркфлоу .github/workflows/collect.yml по образцу compose.yml
(concurrency: state-write, git pull --rebase перед push).
Проверь сухим прогоном, отчитайся по-русски, обнови ПРОМПТЫ.md.
```

## 4. Картинки к постам

Пост без картинки в канале про одежду не читают, а `cover` у постов пустой.
Пресс-фото брендов и кадры показов брать нельзя — канал продаёт рекламу,
и это юридический риск. Рабочие варианты: съёмки магазина, Wikimedia Commons
с проверкой лицензии, свои карточки-шаблоны.

```
В /Users/mke/Mco-mag прочитай CLAUDE.md (раздел про ограничения площадок).
Сделай обложки для постов: поле cover в постах очереди пока всегда пустое.

Начни с самого дешёвого честного варианта — карточки, которую рисуем сами
(шрифт, плашка, заголовок поста): src/cover.py, отправка через
telegram.send_photo_file, публичной ссылки не требуется.
Wikimedia Commons — вторым шагом и только с проверкой лицензии в коде.
Пресс-фото брендов и кадры показов не использовать вовсе.

Зависимостей минимум: Pillow — единственная допустимая новая, и только если
без неё никак. CLI с --dry-run, всё по-русски. Обнови ПРОМПТЫ.md.
```

## 5. Ручной шаг владельца: ключ Anthropic

Не для Claude — для Mike. **Без этого канал не пишет посты вообще.**

`ANTHROPIC_API_KEY` не заведён ни в `.env`, ни в секретах GitHub, поэтому
воркфлоу «Генерация постов» падает на каждом запуске. Ключ берётся
на console.anthropic.com → API keys, и на счёт API нужно положить денег —
он отдельный от подписки на Claude. Порядок расходов: пост 3–5 центов,
батч вдвое дешевле, двадцать постов в очередь — меньше доллара.

Дальше двумя способами: положить ключ в `.env` строкой `ANTHROPIC_API_KEY=...`
(локальные запуски) и завести тем же именем в Settings → Secrets and variables
→ Actions (запуски по расписанию).

Телеграмные секреты (`TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHANNEL_ID`,
`TELEGRAM_ADMIN_ID` с обоими id) и переменная `PUBLISH_TARGET=admin`
заведены 8 сентября 2026 — до этого их не было вовсе, и по этой причине
падали все воркфлоу подряд, а не только генерация.
