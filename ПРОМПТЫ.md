# Эстафета: что делать в следующих сессиях

Файл существует, чтобы новая сессия Claude не пересказывала контекст заново
и не жгла на это токены. В нём — очередь задач и готовые промпты: скопировал
верхний, вставил в новую сессию, работаешь.

**Правило для каждой сессии:** доделал пункт — вычеркни его отсюда, а то,
что всплыло по дороге, впиши новым пунктом с готовым промптом. Файл
переписывается до тех пор, пока в нём не останется пусто: тогда работа
закончена.

Промпт пишется так, будто у читающей сессии нет никакого контекста: что
сделать, где лежит нужное, чем проверить результат. Всё общение — по-русски.

**8 сентября 2026 формат постов утверждён.** Пробники всех четырёх рубрик
ушли ведущим, правок не последовало — журнал `data/feedback.jsonl` пуст,
и промпты переписывать не нужно. Замечание одно: **постам нужны картинки.**

## 1. Картинки к постам

Единственное, что ведущие попросили после просмотра пробников. Поле `cover`
у постов пустое, и посты уходят голым текстом — в канале про одежду такое
не читают.

Отправлять картинки код уже умеет: `publish.send()` шлёт фото по ссылке, если
текст влезает в подпись (1024 знака, посты в этот лимит уложены),
`telegram.send_photo_file()` — файл с диска.

Ограничение, которое нельзя обойти молча: **пресс-фото брендов и кадры показов
брать нельзя** — канал продаёт рекламу, и это юридический риск. Рабочие
источники: съёмки магазина владельца, Wikimedia Commons с проверкой лицензии,
свои карточки-шаблоны.

```
Прочитай CLAUDE.md в /Users/mke/Mco-mag (особенно раздел «Ограничения площадок»)
и src/publish.py.

Ведущие посмотрели пробные посты всех четырёх рубрик и сказали: формат
устраивает, но нужны картинки. Сделай их.

Сначала выясни у владельца одним вопросом, чего он хочет: настоящие фотографии
вещей или свои карточки-заглушки с заголовком поста. Объясни при этом честно,
что пресс-фото брендов и кадры показов каналу, продающему рекламу, брать нельзя,
а живых источников три: съёмки магазина (нужны файлы от владельца),
Wikimedia Commons (лицензия проверяется в коде, вещей там мало) и карточки,
которые рисуем сами.

Дальше сделай то, что он выбрал, самым дешёвым способом, который работает:
— карточки: src/cover.py на Pillow (единственная допустимая новая зависимость),
  заголовок поста на плашке, отправка через telegram.send_photo_file;
— Wikimedia: поиск по названию бренда через их открытый API, проверка лицензии
  в коде, ссылка кладётся в поле cover поста;
— свои съёмки: папка для файлов и привязка картинки к посту по бренду.

Проверить: python -m src.publish --dry-run покажет обложку, а
python -m src.publish --preview-all --force пришлёт очередь ведущим уже
с картинками. Помни: подпись к фото — 1024 знака, отбраковщик держит посты
в этих рамках, и ломать это нельзя.

Отчитайся по-русски и обнови ПРОМПТЫ.md.
```

## 2. Включить в ленту три новые рубрики

Формат утверждён, но `ACTIVE_RUBRICS` в `src/config.py` — по-прежнему только
`history`. Включать имеет смысл вместе с пополнением баз: в
`data/celebrities.json`, `data/unreleased.json` и `data/fresh.json` лежит
по две записи, лента съест их за пару дней.

**Зависит от пункта 4:** без ключа Anthropic генерация не работает вовсе,
включать рубрики бессмысленно.

```
В /Users/mke/Mco-mag прочитай CLAUDE.md. Формат всех четырёх рубрик утверждён
владельцем, ключ Anthropic заведён — пора включать рубрики в ленту.

1. Пополни курируемые базы до 12-15 записей каждую: data/celebrities.json
   (рубрика НА КОМ), data/unreleased.json (НЕ ВЫШЛО), data/fresh.json (НОВОЕ).
   Формат записей смотри в самих файлах. Факты ищи в вебе и проверяй по ссылкам,
   ничего по памяти. Расхождения источников — в поле notes.
   Правило рубрики НЕ ВЫШЛО жёстче общего: без ссылки на подтверждение запись
   не кладётся вовсе, «правдоподобные» подробности запрещены.
2. Добавь ключи fresh, worn, unreleased в ACTIVE_RUBRICS в src/config.py.
3. Проверь: python -m src.compose --dry-run — в плане должны появиться новые
   рубрики в пропорции весов из RUBRICS (45/25/20/10).
Отчитайся по-русски и обнови ПРОМПТЫ.md.
```

## 3. Автосбор поводов для рубрики НОВОЕ

`data/fresh.json` заполняется руками, а по заданию НОВОЕ — единственная рубрика
на автосборе. Ленты проверены и лежат в `data/feeds.json`.

```
В /Users/mke/Mco-mag прочитай CLAUDE.md и ЗАДАНИЕ.md (раздел про рубрики).
Напиши src/collect.py — сборщик поводов для рубрики НОВОЕ: читает ленты
из data/feeds.json, складывает свежие записи в data/fresh.json в том же формате,
что там уже лежит (items с полями brand/what/when/angle/facts/sources/used),
повторы отсекает по data/seen.json через state.fingerprint.

Ограничения проекта: зависимостей минимум (RSS разбирать стандартным
xml.etree, а не feedparser), CLI с --dry-run, докстринг модуля объясняет
решение, всё по-русски.

Важно и должно быть видно в коде: пресс-релиз сам по себе поводом не является —
у записи должна быть связка с историей бренда, иначе пост будет как у всех.

Добавь воркфлоу .github/workflows/collect.yml по образцу compose.yml
(concurrency: state-write, git pull --rebase перед push).
Проверь сухим прогоном, отчитайся по-русски, обнови ПРОМПТЫ.md.
```

## 4. Ручной шаг владельца: ключ Anthropic

Не для Claude — для Mike. **Без этого канал не пишет посты вообще.**

`ANTHROPIC_API_KEY` не заведён ни в `.env`, ни в секретах GitHub, поэтому
воркфлоу «Генерация постов» падает на каждом запуске. Ключ берётся
на console.anthropic.com → API keys, и на счёт API нужно положить денег —
он отдельный от подписки на Claude. Порядок расходов: пост 3–5 центов,
батч вдвое дешевле, двадцать постов в очередь — меньше доллара.

Дальше двумя способами: положить ключ в `.env` строкой `ANTHROPIC_API_KEY=...`
(локальные запуски) и завести тем же именем в Settings → Secrets and variables
→ Actions (запуски по расписанию).

Телеграмные секреты (`TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHANNEL_ID`,
`TELEGRAM_ADMIN_ID` с обоими id) и переменная `PUBLISH_TARGET=admin`
заведены 8 сентября 2026 — до этого их не было вовсе, и по этой причине
падали все воркфлоу подряд, а не только генерация.
