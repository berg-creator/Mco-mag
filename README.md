# Mco mag

Telegram-канал [@mcomagazine](https://t.me/mcomagazine) об одежде, которую носят
осознанно: откуда взялась вещь, кто её придумал и почему она выглядит именно так.

Канал ведёт бот [@Mcomagbot](https://t.me/Mcomagbot). Сервера нет: посты пишет
Claude по курируемой базе фактов, расписание держит GitHub Actions, состояние
лежит обычными файлами в этом репозитории.

Продуктовое задание — в [ЗАДАНИЕ.md](ЗАДАНИЕ.md), устройство кода —
в [CLAUDE.md](CLAUDE.md).

## Как это работает

```
data/brands.json ──► compose ──► content/queue/*.json ──► publish ──► личка
   факты руками      Claude         очередь постов                  с кнопками
                                                                       │
                                                              moderate ▼
                                                                    канал
```

1. **Ты пополняешь базу фактов** — `data/brands.json`. Это единственная ручная
   работа, и она же главная: посты пишутся только из того, что там лежит.
2. **Генератор** дважды в сутки пишет посты впрок и складывает в очередь.
3. **Публикатор** четыре раза в сутки достаёт из очереди самый ранний пост
   и присылает его в личку каждому, кто ведёт канал, с кнопками
   «✅ В канал», «🗑 Удалить», «✏️ Поправить», «⏭ Позже».
4. **Дежурный** раз в час разбирает нажатия. От кнопки до публикации — минуты.

Пока не нажата кнопка, в канал не уходит ничего. Решает тот, кто нажал первым:
второму бот ответит, что поста в очереди уже нет.

## Кнопка «✏️ Поправить» — как править формат постов

Не нравится, как написан пост, — жми «✏️ Поправить». Бот пришлёт сообщение,
на которое надо **ответить** (свайп влево / «Ответить»): напиши, что не так, —
или пришли свой вариант текста поста целиком.

Ответ ложится в `data/feedback.jsonl` вместе с самим постом. Claude читает
этот файл перед тем, как править промпты, и переписывает правила канала
под то, что вы сказали. Пост при этом остаётся в очереди — «Поправить»
ничего не публикует и не удаляет.

Так формат канала правит владелец, а не модель. Второй ведущий может править
из одного Telegram, доступ к Claude ему не нужен.

## Что нужно один раз настроить

### 1. Ключ Anthropic

Заведи ключ на [console.anthropic.com](https://console.anthropic.com) → API keys
и положи денег на счёт API (он отдельный от подписки на Claude).

Порядок расходов: пост стоит примерно 3–5 центов, батч вдвое дешевле обычного
вызова. Двадцать постов в очередь — меньше доллара.

### 2. Секреты на GitHub

Settings → Secrets and variables → Actions → New repository secret:

| Имя | Что кладём |
|---|---|
| `ANTHROPIC_API_KEY` | ключ из пункта 1 |
| `TELEGRAM_BOT_TOKEN` | токен @Mcomagbot от @BotFather |
| `TELEGRAM_CHANNEL_ID` | `@mcomagazine` |
| `TELEGRAM_ADMIN_ID` | твой id и id соавтора через запятую |

Там же на вкладке **Variables** заведи `PUBLISH_TARGET` со значением `admin`.
Когда посты начнут нравиться без правок — поменяешь на `channel`,
и они пойдут в канал сами.

Свой id узнаёшь у [@userinfobot](https://t.me/userinfobot). Каждый, кто ведёт
канал, должен сам написать боту хоть раз: Telegram не разрешает боту начинать
переписку первым.

### 3. Локально (по желанию)

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
cp .env.example .env      # и заполнить
```

**Ключи вписывай в `.env`, а не в `.env.example`.** Первый в git не попадает,
второй попадает — это образец с пустыми полями.

## Ежедневная работа

Ничего. Расписание работает само. Раз в несколько дней приходят посты в личку —
нажимаешь кнопку.

Раз в неделю стоит заглянуть в `data/gaps.jsonl`: туда падает всё, о чём хотели
написать, но фактов не хватило. Это список работы по реальному спросу.

## Как пополнять базу

Открываешь `data/brands.json` и дописываешь бренд или новый сюжет
существующему. **Единица контента — сюжет, а не бренд:** у C.P. Company
их четыре, и каждый даёт свой пост. Двадцать брендов — это сотня постов,
а не двадцать.

```json
{
  "slug": "ma-strum",
  "name": "Ma.Strum",
  "circle": "techno",
  "country": "Италия",
  "city": "",
  "founded": 2009,
  "founder": "",
  "roots": [],
  "in_store": false,
  "notes": "Расхождения источников пиши сюда — модель обязана про них знать",
  "sources": ["https://..."],
  "stories": [
    {
      "id": "ma-strum-first",
      "angle": "О чём именно этот пост",
      "used": false,
      "facts": [
        "Один проверенный факт одной фразой.",
        "Второй факт. Год, город, имя, ткань, тираж — всё, что проверяется."
      ],
      "sources": ["https://..."]
    }
  ]
}
```

Правила, которые лучше не нарушать:

- **Проверяй дату и авторство перед записью.** В моде ходит много красивых
  легенд, которые не подтверждаются. Модель напишет ровно то, что здесь лежит.
- **Расхождения источников — в `notes`.** Тогда пост либо обойдёт спорную дату,
  либо честно скажет, что данные разнятся.
- `used: false` — сюжет ещё не написан. Генератор сам поставит `true`, когда
  пост попадёт в очередь.
- Хочешь, чтобы про бренд написали раньше остальных, — просто удали лишние
  записи из очереди или сгенерируй нужное вручную: `--now`.

## Команды

Проверка — ничего не публикует и не тратит денег:

```bash
.venv/bin/python -m src.publish --check      бот, канал, права, размер очереди
.venv/bin/python -m src.compose --dry-run    план генерации: о чём будут посты
.venv/bin/python -m src.publish --dry-run    что ушло бы в канал следующим
.venv/bin/python -m src.moderate --dry-run   какие нажатия накопились
```

Работа:

```bash
.venv/bin/python -m src.compose --submit        отправить пачку в батч (дёшево)
.venv/bin/python -m src.compose --fetch         забрать готовое в очередь
.venv/bin/python -m src.compose --now 3         написать 3 поста сразу (дороже)
.venv/bin/python -m src.publish --preview-all   вся очередь на просмотр
.venv/bin/python -m src.publish --target channel --force   опубликовать сейчас
```

То же самое есть на GitHub: вкладка Actions → нужный воркфлоу → Run workflow.

## Что придётся делать руками

Это не недоделки, а ограничения площадок — обойти их кодом нельзя.

- **Картинки.** Пресс-фото брендов и кадры показов для канала, который продаёт
  рекламу, брать нельзя: это чужие права. Рабочие источники — собственные съёмки
  магазина, Wikimedia Commons с проверкой лицензии, свои карточки-шаблоны.
  Поле `cover` у поста готово, класть туда ссылку пока надо руками.
- **Цифры просмотров.** Bot API их не отдаёт вовсе — ни чужих, ни своих.
  Для медиакита берёшь их из статистики канала в приложении Telegram.
- **Токен `erid` для рекламы.** Его выдаёт ОРД (Яндекс ОРД, VK ОРД, Медиаскаут),
  а не Telegram и не мы: рекламодатель регистрирует креатив и присылает токен.
  Дальше достаточно поставить у поста `"kind": "ad"`, вписать `advertiser`
  и `erid` — пометка приклеится сама.
- **Reels и TikTok.** Из России не автоматизируются надёжно. VK Клипы и YouTube
  Shorts — можно, но это следующая фаза.
